# Changelog

All notable changes to Corusco are recorded here. The project follows the
compatibility rules in [docs/release-policy.md](docs/release-policy.md).

## 1.4.0 - 2026-11-14

### Added

- `ObservableArrayList.replaceContents` replaces a snapshot in a single change
  set for coherent table refreshes.
- Generated form models expose aggregate validation, dirty state, and a
  revision through `ObservableFormModel`. Observable composite forms let
  dialogs share this state across tabs and coalesce reset and baseline changes.
- `PagedTableBinding` shows the last accepted page during loading and failure.
  The H2 showcase demonstrates server-side filtering and sorting, retry, and
  key-based selection within the same query.
- Opt-in locale-aware number and date converters and typed resource bundle
  lookup through `Resources.fromBundle`.

### Changed

- `SortedList` publishes precise single-row changes, preserves source order
  for equal sort keys, and retains reset events for compound source changes.
- The showcase prepares the H2 observations and generated frame on a worker.

### Fixed

- Worker rejection leaves task tracking intact, and accepted tasks complete
  exactly once.
- Paged data sources publish coherent request and accepted-page state and ignore
  superseded completions.

### Compatibility

- Verified binary compatibility against 1.3.0. Generated names, stable IDs,
  JPMS names, and the default converter choices are preserved.

## 1.3.1 changes included in 1.4.0

### Fixed

- `ObservableTableModel` reports change sets with more than one change (for
  example from `batch`) as `fireTableDataChanged()`. Per-change events
  described intermediate states and made sorted tables (`RowSorter`) throw
  `ArrayIndexOutOfBoundsException`.
- `EdtObservableList` and `EdtObservableReadableCollection` keep an EDT-side
  copy of the elements that changes only when a change set is delivered, so
  EDT reads agree with the events EDT listeners have received while a
  background producer is ahead. Delivery stays in source order when EDT and
  background mutations interleave.
- `ListenerSet` (and so `ObservableArrayList`, `SimpleValue` and the other
  observable emitters) delivers events raised by a listener during dispatch
  after the current event has reached every listener. Previously later
  listeners saw the nested change first, and a `FilteredList` subscribed after
  a mutating listener failed with `IndexOutOfBoundsException`.
- `PreferencesTableStateStore` stores table ids whose encoded name exceeds
  `Preferences.MAX_NAME_LENGTH` under a hashed node name (existing node names
  are unchanged) and wraps Preferences argument/state failures in
  `TableStateStoreException`. `TableStateController` falls back to descriptor
  defaults instead of aborting installation when stored state cannot be
  loaded. A replacement is flushed before it becomes active, so a failed write
  leaves the previous saved state available. Existing table state remains
  readable.
- Annotation processor: primitive `@TextField` components (`int`, and now
  `long`) reject empty text instead of producing a committable form whose
  `toResult()` threw `NullPointerException`; `long`/`Long` text fields are
  supported.
- Annotation processor: invalid `@Regex` patterns are compile errors, and
  generated form models compile each pattern once into a static constant.
- Annotation processor: elements that reference types generated by other
  processors are deferred to a later round instead of failing with "requires
  primitive or declared component types".
- Generated behavior plans bind `@ComboBox` fields.
- `StandardBehaviors.comboBoxBinding`, `BindingFactory.comboBox` and
  `StandardBehaviorKeys.COMBO_BOX_BINDING` provide the combo-box binding.

### Changed

- The annotation processor reports `SourceVersion.latestSupported()` and is
  registered as a Gradle *aggregating* processor, because
  `@SwingCompanionPackage` output depends on the package and every listed
  type. `@SwingCompanionPackage`, `@SwingForm`, `@SwingTable` and `@UiAction`
  now use `CLASS` retention so Gradle can reprocess them incrementally.
- The binary-compatibility gate compares with the published 1.3.0 artifacts,
  resolved from Maven local or Maven Central, and fails if they cannot be
  resolved. CI builds the baseline artifacts from the pinned 1.3.0 release
  checkout before running the gate.
- Build: Gradle 9.9.1; JUnit 6.1.3, FlatLaf 3.8, H2 2.5.252, MigLayout 11.5.2,
  Glazed Lists 1.12.0, JSpecify 1.0.1; newer release, dependency-check,
  CycloneDX and aggregate-javadoc plugins.
- Build: Error Prone and NullAway (JSpecify mode, warnings for now) analyze
  the main sources of published modules; JaCoCo reports are written after
  tests; randomized model tests cover `FilteredList` and `SortedList`.
- Build: a standalone Gradle consumer test verifies that incremental builds
  regenerate and remove Swing companions when their inputs change.
- CI: a `gui-tests` job runs the Swing tests under Xvfb with
  `-PtestHeadless=false`, so GUI-only tests such as `FormDialogShellTest` run.

### Compatibility

- Binary compatible with 1.3.0. The only API additions are the combo-box
  binding methods and behavior key.

## 1.3.0 - 2026-09-18

### Added

- Typed large-data request, page, edit, conflict, and row-identity contracts.
- Fixed-schema dataset and time-series annotations, descriptors, aggregation
  metadata, missing/quality policies, and generated columnar frames.
- `DataSetFrameTableModel` for displaying generated frames without making row
  materialization the table-model contract.
- GitHub Actions verification for pull requests, feature branches, and release
  readiness on `main`.

### Compatibility

- The 1.3.0 release keeps the v1.2.0 binary compatibility baseline.
- Transport-specific integrations, live streaming, backpressure, and generic
  runtime data frames remain deferred.

## 1.2.0 - 2026-06-27

### Added

- Observable readable collection APIs, including sorted-set and mapped
  read-only collection views for business screens that expose ordered data
  without granting mutation rights.
- Read-only table-model and Glazed Lists bridge support for observable readable
  collections.
- `@CoruscoForm` support for abstract class sources, including generated
  immutable result implementations.
- Richer generated form metadata: presentation models, enum option descriptors,
  radio-group behavior, component-state models, dependency metadata, and
  generated behavior bindings.
- `@CoruscoForm`, `@CoruscoTable`, and `@SwingCompanionPackage` as the current
  form/table annotation model with separate core metadata and Swing companion
  generation.
- Multi-form dialog session helpers, including composite form models, Apply,
  Revert, Cancel, dirty-state helpers, action-state models, and active-editor
  focus support.
- Optimized table renderer helpers for high-volume business tables.

### Changed

- The annotation processor is split into focused form, table, action, option,
  dependency, and Swing-companion generation paths.
- Generated form bindings now install through presentation models so field
  values and visual component state can evolve separately.
- Dialog cancel/apply behavior now distinguishes original, current, and last
  applied baselines.

### Compatibility

- Deprecated `@SwingForm` and `@SwingTable` aliases remain available for Corusco
  1.0 source compatibility. They keep the 1.0 same-package Swing companion
  behavior while new code should migrate to `@CoruscoForm`, `@CoruscoTable`, and
  `@SwingCompanionPackage`.
- Binary compatibility with the earlier `1.0.x`/`1.1.x` API baseline is not a
  release blocker for this phase; consumers should validate source changes
  against the 1.2 API surface before upgrading.

## 1.0.0 - 2026-06-17

### Added

- `SortedList` and `MappedList` read-only observable collection views.
- Generated `<Form>Bindings` facades for installing generated behavior plans.
- Generated enum combo-box option metadata through `@ComboBox(enumOptions)`.
- Generated command factories and ordered descriptor/menu/toolbar metadata for
  `@UiAction` owners.
- `FormDialogShell` as a minimal native `JDialog` host for `FormDialog`.
- JApiCmp-based binary compatibility gate for runtime modules, with first-run
  `v1.0.0` baseline establishment under `.machine_env/api-baselines`.

### Changed

- Development version is now `1.0.0`.
- Local release readiness is exposed as `verifyReleaseReadiness`; the former
  `verifyPreviewReleaseReadiness` task remains as a compatibility alias.
- `corusco-test` is internal test support and is no longer part of the
  published artifact set.
- Preview package-surface review now includes the annotation subpackages:
  `annotations.command`, `annotations.form`, `annotations.help`,
  `annotations.table`, and `annotations.validation`.

### Breaking Changes

- Annotation imports are split by authoring area after `v0.1.0-preview`.
  Replace root-package annotation imports with the focused subpackages:
  form annotations from `cz.auderis.corusco.annotations.form`, table
  annotations from `.table`, validation constraints from `.validation`,
  command annotations from `.command`, and help metadata from `.help`.

## 0.1.0-preview - 2026-06-14

### Added

- Maven-local publication wiring for library modules with source and Javadoc
  jars.
- `verifyMavenLocalPublication` to verify local publication artifacts.
- Release policy covering preview semantic versioning and compatibility rules.
- JPMS module descriptors for published library modules.
- `verifyExamplesAgainstPublishedArtifacts` to compile examples from
  Maven-local Corusco artifacts.
- Preview API/package review gates for published packages and runtime
  reflection policy.
- `verifyGeneratedJavadocs` and `verifyPreviewReleaseReadiness` for local
  preview release checks.

### Changed

- Documentation now treats `corusco-glazedlists` as a first-class optional
  published module and clarifies that `corusco-examples` is an in-repository
  consumer rather than a published artifact.

### Breaking Changes

- None.

### Scope

- First preview artifact set for the roadmap minimum viable release.
- Typed runtime primitives, generated metadata/form/table support, Swing
  bindings, table state, dialogs, async validation, Glazed Lists interop,
  testing helpers, documentation, and examples.

### Release Gate

- All examples compile.
- Maven-local publication can be consumed by a local application.
- Generated Javadocs are readable.
- No core API depends on runtime reflection or a legacy reflection module.
